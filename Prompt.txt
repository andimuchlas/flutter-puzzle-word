Design and prototype a complete mobile casual crossword / TTS word puzzle game.

IMPORTANT:
The UI and UX MUST be designed according to the Stitch-generated design system and visual language.
Stitch is the SOURCE OF TRUTH for the entire UI/UX.
Do NOT reinterpret the design into a generic Flutter UI.
Do NOT redesign screens independently.
Do NOT introduce a different visual style between screens.

The final design should feel like a real shipped mobile game, not an AI-generated UI concept.

==================================================
PRODUCT
==================================================

Game type:
- Wordscapes-style Anagram Crossword (Teka Kata Anagram Silang)
- Tema Utama: Nusantara (Kekayaan alam, budaya, rempah, bahari, dan kepulauan Indonesia)
- Bahasa: Bahasa Indonesia untuk seluruh kosakata teka-teki, kamus anagram, dan kata bonus
- Tampilan Zen: Full-bleed scenic wallpaper bentang alam Nusantara (Bali, Maluku, Candi Jawa, Borneo, Raja Ampat)
- Android-first
- Portrait orientation
- One-handed mobile interaction
- Short play sessions: approximately 2–10 minutes
- Relaxing, zen, but satisfying gameplay
- Primarily offline playable
- Monetized through:
  1. Optional rewarded ads
  2. Remove Ads purchase
  3. Powerup purchases

Core gameplay is a Wordscapes-style anagram crossword without trivia questions:
- Floating Crossword Grid: Kotak-kotak kata transparan mengambang di atas pemandangan alam Nusantara. Sel kosong 100% transparan, sel terisi berwarna vibrant indigo dengan huruf tebal.
- 100% Interconnected Grid Rule: Seluruh kata dalam grid teka-teki silang WAJIB terhubung dalam satu kesatuan graf (saling bersilangan tegak lurus). TIDAK BOLEH ada kata atau kluster kotak yang terpisah/terisolasi (disjoint / terpisah).
- Anagram Validity: Seluruh kata di grid dan kata bonus wajib merupakan anagram sah yang disusun dari huruf-huruf pada roda huruf sesuai jumlah/frekuensinya.
- Letter input mechanism: Circular tactile frosted letter wheel di bagian bawah dengan drag-ribbon trail, haptics, dan word preview capsule.
- Action Hub: Tombol Shuffle dan Target Hint di sisi kiri roda huruf; tombol Bohlam Hint dan Rocket Word Reveal di sisi kanan roda huruf.
- Anagram & Bonus Words: 5 level playable bertema Nusantara murni berbasis anagram huruf roda, dilengkapi sistem Kata Bonus (+koin).
- Responsif satu layar penuh (zero-scroll) untuk ponsel maupun tablet.

==================================================
DESIGN PHILOSOPHY
==================================================

The interface should look intentionally designed by a professional mobile game designer.

Avoid the common appearance of AI-generated interfaces:

- No excessive gradients
- No excessive glassmorphism
- No random floating cards
- No excessive pill-shaped buttons
- No generic dashboard layouts
- No excessive shadows
- No neon colors
- No meaningless decorative elements
- No excessive icons
- No stock-looking illustrations
- No generic "premium SaaS" appearance
- No oversized typography without purpose
- No excessive rounded rectangles
- No visual clutter

Use a restrained, cohesive visual language.

The game should feel:
- warm
- approachable
- polished
- calm
- playful
- readable
- tactile
- game-like
- production-ready

Visual personality should come primarily from:
- typography
- spacing
- crossword grid
- level/map presentation
- small environmental illustrations
- subtle animation
- feedback states

NOT from excessive visual effects.

The screen should immediately communicate:

- Current world/island
- Continue playing

- Daily reward
- Navigation

Example structure:

==================================================
SCREEN 2 — WORLD / ISLAND MAP
==================================================

Create a visual progression map.

The player progresses through multiple themed islands or locations.

The map should visually communicate:

- Completed levels
- Current level
- Locked levels
- World progression

Use a simple path-based progression system.

Each level node should have clear states:

LOCKED
AVAILABLE
CURRENT
COMPLETED

Completed levels may show stars or completion indicators.

The map should feel like part of the game world, not like a generic UI list.

Avoid excessive UI panels covering the map.

If a separate level selection screen is used, keep it lightweight.

Display:

- World title
- World progress
- Level nodes
- Completion status
- Stars

Do not use a dense spreadsheet/grid of level numbers.

The player should understand where they are in progression immediately.

==================================================
SCREEN 4 — CROSSWORD / TTS GAMEPLAY
==================================================

THIS IS THE MOST IMPORTANT SCREEN.

The crossword board is the primary visual identity of the game.

Use a real crossword/TTS-style grid.

Example:

┌─────────────────────────┐
│ ← Tropical Coast    1,450│
│                         │
│       LEVEL 12          │
│                         │
│    ┌───┬───┬───┬───┐    │
│    │ 1 │ A │ P │ P │    │
│    ├───┼───┼───┼───┤    │
│    │   │ E │   │   │    │
│    ├───┼───┼───┼───┤    │
│    │ C │   │   │   │    │
│    └───┴───┴───┴───┘    │
│                         │
│  "A tropical fruit..."   │
│                         │
│       A P P L E         │
│                         │
│   [Hint]       [Skip]   │
└─────────────────────────┘

The exact visual layout should follow the Stitch design system.

Gameplay requirements:

- Crossword cells must be large enough for touch interaction.
- Selected cell has a clear visual state.
- Selected word is visually highlighted.
- Filled letters are immediately readable.
- Incorrect answers have clear but subtle feedback.
- Correct answers animate into place.
- Completed words have a satisfying visual response.
- Completing the puzzle has a stronger success animation.

The grid must remain the dominant element.

Do not allow decorative elements to compete with the crossword.

==================================================
CROSSWORD INTERACTION
==================================================

The user should be able to:

- Tap a crossword cell
- Select a word
- Enter letters
- Change selected word direction where applicable
- Remove a letter
- Use hints
- Reveal a letter
- Reveal a word
- Skip / continue where appropriate

Input should feel fast and tactile.

Avoid creating a traditional text input field.

Use a custom game keyboard if appropriate.

Keyboard requirements:

- Large touch targets
- Clear hierarchy
- Comfortable spacing
- Minimal visual noise
- Clear pressed state
- Disabled state for unavailable letters

==================================================
UX PRINCIPLES
==================================================

Follow these rules across the entire product:

1. The player should always understand what to do next.

2. Every screen should have one obvious primary action.

3. Avoid unnecessary confirmation dialogs.

4. Keep navigation shallow.

5. Preserve game state automatically.

6. Never punish accidental taps.

7. Use animation to communicate state changes, not decoration.

8. Use consistent interaction patterns.

9. Keep touch targets comfortable for mobile.

10. The crossword board must remain the primary gameplay focus.

11. Monetization must never interrupt active puzzle solving unnecessarily.

12. Rewarded ads should always be opt-in.

13. Avoid dark patterns.

==================================================
ANIMATION
==================================================

Animations should be subtle and purposeful.

Use animation for:

- Button press
- Cell selection
- Letter placement
- Correct answer
- Incorrect answer
- Word completion
- Level completion
- Reward collection
- Map progression

Avoid:

- Constant floating animations
- Excessive particle effects
- Large screen transitions
- Long animations that delay gameplay

Gameplay should feel responsive.

Target animation duration:
approximately 120–350ms for normal interactions.

Major completion animation:
approximately 500–1000ms.

==================================================
RESPONSIVE DESIGN
==================================================

Design primarily for Android portrait phones.

Support different phone sizes and aspect ratios.

The UI must not depend on a fixed screen resolution.

Important:

- Crossword grid should scale proportionally.
- Text must remain readable.
- Buttons must remain tappable.
- Bottom navigation must remain accessible.
- Content must respect safe areas.
- Avoid elements touching screen edges.

Design around mobile constraints, not desktop layouts compressed into a phone.
